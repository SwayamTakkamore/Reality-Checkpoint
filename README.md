# Reality Checkpoint

**The screen is a portal, not a destination.**

An AI-powered real-world adventure game. You tell it how much time you have and what
you are in the mood for; it hands you a bespoke mission, you put the phone away and go
live it, and when you come back you describe what happened. A local open-weight model
reads your reflection, scores it, and files what you found into a growing narrative of
your own neighbourhood.

Built for **Hacktoberfest 2026 — Week 1: Touch Grass**.

> Every quest evaluation runs against a model on your own machine. No accounts, no API
> keys, no telemetry. If the model is unavailable the app degrades to a deterministic
> heuristic engine and keeps working.

---

## The loop

```
Portal  →  30-second setup        time budget · theme · mood
        →  Bespoke mission        generated by a local model, safety-checked
        →  Dormant mode           countdown ring, chime when time is up
        →  Reflection chamber     you describe what you actually experienced
        →  Evaluation             quality score, XP, a memory, a Socratic question
        →  Storyline              discoveries compound into a narrative
```

The mission screen is deliberately quiet: a mission, a sensory focus, safe
boundaries, and a question to hold. Then you leave.

---

## Five storylines

Each is a long-running arc with chapters that unlock as you complete quests in it.

| Storyline | What it trains |
| --- | --- |
| **Architecture of Shadows** | Light, shadow, and the built form |
| **Urban Biomecartography** | Mapping the living systems of a street |
| **Acoustic Commons** | Tuning into the shared soundscape |
| **Micro-Physics** | Small forces you can hold in your hand |
| **Ephemeral Encounters** | Fleeting human and animal moments |

Progress is stored per player and per storyline; completing a chapter unlocks the next.

## Quick start

One command builds the interface if needed and serves everything:

```bash
./start.sh
```

The built app is served by the API process itself at **http://localhost:8000**.
Useful variants:

```bash
./start.sh --api-only     # FastAPI backend only        → http://localhost:8000/docs
./start.sh --ui-only      # Vite dev server with HMR    → http://localhost:5173
./start.sh --rebuild      # force a fresh frontend build
```

`start.sh` finds `npm` via `npm`, `corepack npm`, or `bun`, in that order. If npm is
managed by corepack on your machine, nothing extra is required.

### Manual setup

```bash
# Backend
pip install -r requirements.txt
cd backend && python -m uvicorn main:app --reload --port 8000

# Frontend (second terminal)
cd frontend && npm install && npm run dev
```

### With a local model

Install [Ollama](https://ollama.com) and pull an open-weight model:

```bash
ollama pull glm-4.7-flash
ollama serve
```

The app detects it automatically and the diagnostic bar switches from `heuristic`
to `ollama`, with live model name and latency.

| Variable | Default | Meaning |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama endpoint |
| `OLLAMA_MODEL` | `glm-4.7-flash:latest` | Model used for generation and evaluation |
| `OLLAMA_TIMEOUT` | `45` | Per-request timeout in seconds |
| `REALITY_DISABLE_OLLAMA` | unset | Set to `1` to force heuristic mode |
| `REALITY_DB_PATH` | `backend/reality_checkpoint.db` | SQLite location |
| `REALITY_HOST` / `REALITY_PORT` | `0.0.0.0` / `8000` | Backend bind address |
| `REALITY_API` | `http://localhost:8000` | Target of the Vite `/api` proxy |

## API

Base path `/api`. Interactive docs at `/docs`.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/status` | Service health, AI mode, model, latency, uptime |
| `GET` | `/api/player?player_id=` | Level, XP, streak, attention total, active quest |
| `GET` | `/api/storylines?player_id=` | Five arcs with chapter unlock states and progress |
| `POST` | `/api/quests/generate` | Create a mission from a time budget, theme, and mood |
| `GET` | `/api/quests?player_id=` | Quest history |
| `POST` | `/api/quests/reflect` | Evaluate a reflection, award XP, extract a memory |
| `GET` | `/api/memories?player_id=&search=&category=&limit=` | Field journal entries |
| `GET` | `/api/journal/export?player_id=` | Full journal as Markdown |

Example:

```bash
curl -s localhost:8000/api/quests/generate \
  -H 'content-type: application/json' \
  -d '{"time_minutes":10,"theme":"auditory","mood":"curious"}' | python -m json.tool
```

```bash
curl -s localhost:8000/api/quests/reflect \
  -H 'content-type: application/json' \
  -d '{"quest_id":"<id>","reflection_text":"I stood still for ten minutes..."}' \
  | python -m json.tool
```

### Progression

Each level costs `100 + (level - 1) * 75` XP. A reflection earns XP proportional to its
evaluated quality (clamped to 10–150), so a specific, sensory, first-person account
outperforms a one-line summary.

## Safety

Real-world missions need real-world guardrails, so safety is deterministic and enforced
in code, not delegated to the model.

- Every generated quest — model-written or heuristic — passes through
  `safety.validate_quest` and `safety.enforce` before it reaches the player.
- Unsafe instructions are scrubbed or rejected; a safe fallback mission is substituted
  rather than failing the request.
- Each quest carries explicit **safe boundaries** that set what the player may not do.
- User-supplied hints and reflections are sanitised for prompt-injection patterns before
  being placed into a model prompt.

## Tests

```bash
cd backend && python -m pytest test_backend.py -q
```

The suite exercises every endpoint plus the failure paths: invalid time budgets, unknown
quest ids, empty reflections, out-of-range ratings, bad pagination, and the heuristic
fallback when no model is reachable. `REALITY_DISABLE_OLLAMA=1` is set by the tests so
they are deterministic and offline.

## Design

Obsidian near-black ground, forest-green accents, warm paper text. Inter for the
interface, Spectral for prose, JetBrains Mono for numbers and timing. The countdown ring
breathes rather than ticks; the chime is a 528 / 660 / 792 Hz sine triad, not an alarm.
Motion respects `prefers-reduced-motion`.
